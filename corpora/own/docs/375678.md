# What is the community feedback weight in deciding if a UI/UX is going to be "committed" or reverted?

I have recently noticed a change in the post list when a significant part of it became almost unreadable when compared to the previous version. I did not like it and I was pleased to find out that I am far from being the only one not liking it.

This change (along with others in the past) received very little love from the community and I am wondering if this input is considered in the SO development team's decision to go on with the change or revert it.

I am specifically asking for in the context of this recent case because any user accessing the list is forced to live with it. This is opposed to the case when the layout changes impact is easier to check (e.g. user interaction with some links decreases and signals that something is wrong with the new layout).

What is the community feedback weight in deciding if a UI/UX is going to be "committed" or reverted? Is there any? Or only some metrics from A/B testing or similar matter in this type of decision?
